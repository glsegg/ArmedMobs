# 指挥系统设计（指挥道具 ×3 · 信号棒 · 信号点方块）

> 状态：**设计已定稿（3 条待确认项已由用户拍板），等待实现**。
> 所有单位归属都取自仓库里的实体标签，不是推测。

## 1. 阵营（实测，来自 `data/tarkovscav/tags/entity_types/`）

| 阵营 | 标签 | 包含的单位 |
| --- | --- | --- |
| 村民方 | `#tarkovscav:faction_village` | `minecraft:villager`、`wandering_trader`、`iron_golem`、`snow_golem` + `tarkovscav:gunner_villager`、`sniper_villager`、`usec_villager`、`elite_villager` |
| 掠夺者方 | `#tarkovscav:faction_illager` | `minecraft:pillager`、`vindicator`、`evoker`、`illusioner`、`ravager` + `tarkovscav:gunner_pillager`、`sniper_pillager`、`bear_pillager`、`elite_pillager` |
| 暴徒方 | `#tarkovscav:faction_scav` | `tarkovscav:scav` |

**已确认（用户原话：「两个负责不同的阵容单位 不能跨级去管其他阵容的」）**：
每件指挥道具**严格阵营锁定**——村民方道具只影响村民方，掠夺者方道具只影响掠夺者方，暴徒方道具只影响暴徒方；
**绝不跨阵营**。命令判定只看"目标单位属于哪个标签"，与它是不是敌对、是谁刷出来的无关。

## 2. 三件道具 + 一个方块

| 名称（暂定） | 类型 | 作用 |
| --- | --- | --- |
| 村民方指挥道具 | 物品 | 指挥范围内的 `faction_village` 单位向**当前选中的标记**缓缓推进 |
| 掠夺者方指挥道具 | 物品 | 同上，只影响 `faction_illager` |
| 暴徒方指挥道具 | 物品 | 同上，只影响 `faction_scav` |
| 信号棒 | 投掷物 | 扔出去，落地生成一个**存活 5 分钟（6000 tick）**的标记 |
| 信号点 | 方块 | 放下即生成**永久**标记；挖掉即失效 |

三者都是**工具而非消耗品**（信号棒扔出去留在落点，可以捡回来）。

## 3. 标记：中立 + 可编号多目标（已确认）

**用户原话：「标记中立，指挥工具可以控制阵容去 ABCD 哪个标记点」**。所以：

* 标记**不属于任何阵营**：任何一件指挥道具都能把任何标记当作目标；
* 同维度内可以**同时存在多个标记**，按创建顺序自动编号 **A、B、C、D…**（取第一个空闲字母）；
* 玩家身上有"**当前选中标记**"这一状态；指挥道具的右键语义围绕它展开（见 §4）；
* 标记来源三类：**指挥道具右键地面**（临时标记）、**信号棒**（5 分钟）、**信号点方块**（永久）；
* 新命令（挂现有 `/armedmobs` 树下）：
  * `/armedmobs marks` —— 列出当前维度的全部标记：字母、坐标、来源、剩余时间；
  * `/armedmobs marks remove <字母>` —— 删除某个标记；
  * `/armedmobs marks clear` —— 清空当前维度的标记（调试用）。

## 4. 操作方式（右键语义）

| 操作 | 结果 |
| --- | --- |
| 指挥道具 **右键方块** | 在该处**新建标记**（自动编号）→ 把它设为当前目标 → **立刻下令**范围内同阵营单位向它推进 |
| 指挥道具 **潜行 + 右键方块** | 只**新建标记**，不下令（先把 ABCD 都摆好，再逐个下令） |
| 指挥道具 **右键空气** | 向**当前选中的标记**下令推进 |
| 指挥道具 **潜行 + 右键空气** | **切换当前目标**（A → B → C…循环），并在聊天栏显示"当前目标：B (x, y, z)" |
| **扔信号棒** | 落点生成标记（5 分钟），自动编号；有粒子与音效，倒计时结束自动消失 |
| **放置信号点方块** | 生成永久标记；破坏方块则标记立即失效 |

## 5. 推进逻辑（"不是一股脑冲"的关键）

被下令的单位获得一个**命令层**（`AdvanceOrder`），它只覆盖"去哪、多快"，不覆盖战斗判定：

1. **只影响同阵营且在范围内的单位**：默认半径 **32 格**（可配置）；野生的同阵营单位同样生效。
2. **速度**：默认**步行 ×0.65**（"缓缓"），**不冲刺**，可配置。
3. **协调跃进**：
   * 每个小队分**推进组 / 掩护组**，一组前进时另一组留在掩体后观察，由现有
     `gun/SquadCoordinator` 的交替掩护轮换驱动（复用已有机制，不新写第二套协同）；
   * 各单位**错峰出发**（按实体 id 打散出发 tick），避免同一 tick 全体起步；
   * 移动途中仍走**现有掩体寻路**（`CombatTactics.bestCover`），不是直线冲锋。
4. **到达即结束**：进入标记点半径 **4 格**内命令自动解除，恢复自主 AI。
5. **战斗优先**：途中遇敌照常交战（瞄准/开火/掩体/压制/换弹），不会为了命令傻冲；
   交火结束后命令未过期则继续推进。
6. **自保优先**：血到该档位撤退阈值时**照旧撤退**，撤退期间**不接受**新命令；
   撤退结束且命令未过期则继续。
7. **命令过期**：信号棒标记过期 → 相关命令失效；信号点方块的命令不过期。

## 6. 数据与持久化

* `CommandMark`（`SavedData`，**按维度**）：`{label, pos, expiresAtTick(-1 = 永久), source}`，中立、可多个。
* 玩家的"当前选中标记"：按玩家 UUID 记录在服务端（`SavedData`），重登保留；标记消失则回落到第一个可用标记。
* `AdvanceOrder`：写在**单位自己身上**（实体持久化 NBT）：`{targetPos, issuedTick, expiresTick}`，
  所以重登、区块卸载再加载都不会丢。
* 信号点方块带 `BlockEntity`（记录坐标/编号），破坏时注销标记。

## 7. 新增配置键（都会写进 README 与指令表）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `command.enabled` | `true` | 指挥系统总开关 |
| `command.radius` | `32` | 指挥道具影响半径（格） |
| `command.speedScale` | `0.65` | 推进速度倍率（1.0 = 正常步行） |
| `command.arrivalRadius` | `4.0` | 视为"到达"的半径 |
| `command.stickDurationTicks` | `6000` | 信号棒标记存活时间（5 分钟） |
| `command.coordination` | `true` | 交替掩护 + 错峰（关闭 = 各自直接走） |
| `command.maxMarks` | `12` | 同维度标记上限（超出时最旧的失效） |

## 8. 已拍板的三个决定

1. **要**第三件「暴徒方指挥道具」（用户选"也要"）——三件道具同构，只差阵营参数与材质/language。
2. **严格阵营锁定**，不跨阵营：村民方/掠夺者方/暴徒方道具各管各的（用户原话见 §1）。
3. **标记中立**，可同时存在多个并编号 A/B/C/D，玩家可切换当前目标（用户原话见 §3）。

## 9. 验收（可静态 / 无头复核的部分）

1. **阵营锁定**：村民方道具对掠夺者方与暴徒方单位**零影响**；三件道具互不越界（逐个断言）。
2. **标记生命周期**：信号棒标记 6000 tick 后消失；信号点标记破坏方块即失效；按维度隔离；字母编号在删除后能被复用。
3. **目标切换**：潜行右键空气按 A→B→C 循环；当前目标被删除后自动回落到可用标记；无标记时右键给出明确提示而不是静默失败。
4. **命令写入/持久化**：重登后命令仍在；到达半径内自动解除；过期自动解除。
5. **自保优先**：模拟"命令进行中 + 血量跌破撤退阈值"→ 必须进 `RETREAT` 且不再前进；撤退结束且命令未过期 → 恢复推进。
6. **协调**：关闭 `command.coordination` 时全体同 tick 起步；开启时出发 tick 必须分散，
   且至少出现一次"一组移动、另一组静止"的交替（确定性模拟断言，像 `selftest_ai_profiles.js` 那样单测）。
7. **注册完整性**：三件道具 + 信号棒 + 信号点方块 + BlockEntity 的模型、程序生成材质、双语 lang、配方、创造栏齐全。
8. **全套 `selftest.ps1` 绿** + 服务端零注册表报错启动 + 世界能加载（日志为证）。

## 10. 实现边界（我做不到的部分）

* 手感与观感（推进节奏、粒子样式、右键手感、编号可读性）**只能你进游戏判断**；
  我能给的是静态门禁 + 服务端加载验证 + 确定性模拟（AI 状态机、协调轮换、过期/到达/撤退判定）。
* 材质是**程序生成**的 16×16（沿用现有做法，不引入任何第三方美术）。
