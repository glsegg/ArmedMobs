# 爬梯 / 垂直移动设计（九个武装单位）

> 状态：**设计稿，待实现**。目标：让 `scav` 与八个武装单位能像玩家一样**正常上下梯子**，
> 而不是卡在梯井底、掉进楼板洞、或者干脆上不了楼。

## 0. 现状（实测，不是推测）

| 事实 | 证据 |
| --- | --- |
| 模组**没有任何**梯子/攀爬代码 | 全仓库搜 `LADDER` / `onClimbable` / `isClimbing` / `climb`：**0 命中** |
| 生成器**已经**建了梯井与梯子 | `CityStructureGen` 的 `Role.LADDER`、`shaftX/shaftZ = x0+1/z0+1`，每层楼板开洞 |
| 出厂结构里确实有梯子 | `city_small.nbt` 调色板含 `minecraft:ladder`；据点有 18 个梯子列（每栋 1 个） |
| 原版怪物不会爬 | 1.20.1 的 `WalkNodeEvaluator` 不为梯子生成**垂直边**，`Mob`/`LivingEntity` 也没有"贴梯上行"的移动分支 |
| 玩家的爬梯是特例 | 玩家靠 `LocalPlayer#aiStep` 里的 `onClimbable()` 分支 + 输入；怪物没有这条 |

**结论**：这不是"调个参数"，而是**三层都要补**：垂直寻路 / 移动 / AI 意图。

## 1. 三层设计

### 第 1 层：垂直寻路（怎么知道"能上去"）
原版 `WalkNodeEvaluator` 只走水平 + 单格跳跃/下落，**梯子竖井在它眼里是墙**。两条路线：
* **A（便宜、推荐）"梯子链接"**：不改造寻路器，而是加一个**垂直链接检测器**：当目标在同一栋楼的另一层时，
  在半径内找"合法梯子列"（梯子方块 + 前方 2 格净空 + 每层有可用开口），把路线拆成
  "走到梯脚 → 爬 → 从目标层开口走出 → 继续走"。寻路器只负责水平段。
* **B（彻底、贵）** 自定义 `NodeEvaluator`/`PathNavigation`：给梯子生成上下边，让 A\* 自己串起来。
  好处是任何地图都能用；代价是要替换九个实体的导航实例，还要处理"爬到一半被打断"的重入问题。

本次先做 A，B 作为后续可选项（A 已经覆盖生成器造出来的所有竖井）。

### 第 2 层：移动（怎么爬）
* 判定"贴在梯子上"：`onClimbable()`（梯子/藤蔓/脚手架通用）+ 前方是梯子方块。
* 向上：每 tick `setDeltaMovement(≈0, climbSpeed, ≈0)`（默认 `0.15`，可配置），**面向梯子**，
  并**暂停普通地面导航**（否则寻路器和爬梯会互相打架）。
* **关闭梯上摔落伤害**（从梯子掉一格不算摔）。
* 到达目标层时：把单位挪进该层开口（先确认落脚格可站立 + 上方 2 格净空，否则继续爬/停下）。
* 向下：同样贴梯下行（默认比上行慢），而不是直接跳——现在它们是从楼板洞**摔下去**。

### 第 3 层：AI 意图（什么时候爬）
* `LadderClimbGoal`（优先级高于徘徊、**低于**战斗与撤退的紧迫部分）：只有"目的地不在本层 + 找到合法梯子列"时才激活。
* 爬梯期间：**不开火、不换弹、不找掩体**（枪口朝天打不了）；`GunBrain` 让位（可以用现有"Villager 脑子停用"的同款写法）。
* 与已有系统的接口：
  * **指挥系统**：命令点在不同层时，路线自动包含梯子（否则命令会永远"到不了"）。
  * **狙击手选点**：把"只有爬梯才能到的射击位"计入可达性（现在它可能选了一个自己上不去的位置）。
  * **撤退**：允许用梯子下楼（不再从洞里摔）。
  * **驻军**：在楼内生成的单位如果目标在上层，能自己上去。
* 中断条件：命令取消 / 标记消失 / 目标死亡 → 停在当前层就近落地（不许悬在半空）。

## 2. 配置键（会写进 README 与指令表）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `ladder.enabled` | `true` | 总开关（false = 回到"不会爬"的旧行为） |
| `ladder.climbSpeed` | `0.15` | 上行速度（格/tick，玩家约 0.2） |
| `ladder.downSpeed` | `0.10` | 下行速度 |
| `ladder.searchRadius` | `8` | 愿意为爬梯绕多远去找一个竖井 |
| `ladder.maxHeight` | `48` | 单次连续攀爬的最大高度（防止无限爬） |
| `ladder.combatWhileClimbing` | `false` | 是否允许在梯子上开火（默认禁止） |
| `ladder.fallDamageInShaft` | `false` | 梯井内是否恢复摔落伤害（默认关闭） |

## 3. 生成器侧要顺手核对的一件事

出厂梯井必须**真的能爬**：每层开口与梯子**相邻**、梯子从下层楼板**连续到上层**、开口上方 2 格净空。
这一条会做成断言（对六个结构逐层检查，打印每个竖井的"可攀爬性"），如有不合规的竖井就修生成器并重生成。

## 4. 验收（可静态/无头复核的部分）

1. **竖井合法性**：六个结构里每个梯子列从下到上连续、每层开口相邻且 2 格净空（打印逐列结论）。
2. **决策**：确定性单测——"同层目标不触发爬梯 / 目标在上层且半径内有梯子 → 触发 / 半径内没梯子 → 不触发而是就近寻路"。
3. **状态机**：上行、下行、到达走出、中断落地（四个分支各自的终止条件与落点合法性）。
4. **AI 让位**：爬梯期间 `GunBrain` 不开火、不换弹（静态断言 + 单测）。
5. **摔落处理**：梯井内不掉血；从梯子上被打下来时恢复正常摔落规则。
6. **九个实体全覆盖**：断言九个实体都装了这套 goal/导航（不能只给村民装）。
7. **服务端实测（尽力）**：用 RCON 搭一个梯井（`/setblock`），在底部召唤一个单位，用指挥命令把标记点放到上层，
   轮询它的 Y 看是否真的爬上去。**已知障碍**：先前有代理发现那个测试世界里连原版闲逛都不移动，
   所以若这次仍无法让单位移动，就必须**如实说明"只做到模拟级验证"**，不能声称看过它爬。

## 5. 我做不到的部分

* 观感（爬梯动作是否自然、枪在背上的姿势、速度手感）**只能你进游戏看**。
* 若实现为方案 A，那么**别的模组的地形里"非标准梯井"不一定能被识别**（我们只保证自己生成的竖井 + 通用梯子方块检测）。
