# 城市争夺 / 占领设计（主世界限定）

> 状态：**设计稿，待实现**。用户口径（原话）：
> 「占领城市的这种玩法**只在主世界**有」「如果不被占领会**一直刷几个阵容的单位，直到一方兵力消失**（思路和战地一样）」
> 「**废土世界完全是各种人乱斗。不需要占领**」。

## 1. 两个维度的规则不同（这是本设计的第一原则）

| | **主世界** | **废土 `tarkovscav:urban_wasteland`** |
| --- | --- | --- |
| 阵营结构 | 每栋楼一个阵营（可统一、可混编） | 同样按楼分配，但**没有归属概念** |
| 强度池 / 血条 HUD | **有**（20~100 按城市规模） | **没有** |
| 增援刷新 | 双方池 > 0 就**持续刷**（战地式拉锯） | 一直混战，**不记账、不判定胜负** |
| 结束条件 | 一方池归零 → 该阵营在该区域**停止刷新**，另一方**占领** | 无（永久乱斗） |
| 玩家靠近 | 进入"争夺中"状态，HUD 出现 | 无特殊状态（但照样会被卷入） |

实现上就是把整套争夺逻辑挂在**维度判断**后面（`level.dimension() == OVERWORLD`），
废土里只保留"按楼分配阵营 + 各自开打"，**不建池、不出 HUD、不判胜负**。

## 2. 主世界争夺的完整流程

1. **首次接近**（沿用现有驻军触发器：半径 64、每 100 tick、只查已加载区块）：
   * 掷定该城每栋楼的阵营并记账（永久）；
   * 按楼把刷怪笼内容改写成该楼阵营的部队单位；
   * **建立强度池**：每个在该城出现的阵营一条，初始值 = `20~100`（按城市规模：建筑数/包围盒面积换算，可配置上下限）；
   * 结算一次初始驻军（沿用现有驻军：每队 1~5 人、可配优质队长）。
2. **拉锯阶段**（池都 > 0 时）：
   * 双方持续获得增援（刷怪笼继续工作 + 自然刷怪按楼过滤 + 驻军按间隔补员）；
   * **每死一个该阵营单位 → 该阵营池 −1**（每次扣多少可配置；是否只算玩家击杀默认"全都算"，因为战地式玩法里友军互殴也该掉血——这一点见 §5 待确认）；
   * 敌对阵营之间**本来就会互相攻击**（模组已有阵营系统），所以池会自己往前推进，玩家只是加速器。
3. **结束（占领）**：
   * 池 = 0 的阵营在该区域**不再刷新**：自然刷怪、刷怪笼、驻军补员三条路径**全部**被拦住；
   * 幸存阵营成为该区域唯一刷新的持枪单位 → 该城"被占领"；
   * `[capture] <城> 被 <阵营> 占领（<池0阵营> 兵力耗尽）` 日志 + HUD 上该阵营条变灰并标注"已占领"。
4. **可逆性**：占领**不写死在地形里**，只记在账本里；若日后玩家把幸存阵营也清空（默认不判负，见 §5），或手动用命令重置，则该城重新进入争夺。

## 3. 池归零后"停止刷新"的实现方式（关键技术点）

刷怪笼是**世界里的方块实体**，内容写死后不会自己变。所以"该阵营不再刷新"要在**三条路径**同时生效：

| 路径 | 做法 |
| --- | --- |
| 自然刷怪 | 现有按楼过滤上再加一层：该楼阵营池 = 0 → 直接取消（`CitySpawnEvents`） |
| **刷怪笼** | Forge 的 `LivingSpawnEvent.SpecialSpawn` 对刷怪笼刷新**会触发且可取消**：池 = 0 的阵营在此取消。**不改方块内容**（非破坏、可逆），笼子保留原外观 |
| 驻军增援 | 补员前查池；池 = 0 不再补 |

> 备选（**不做**，除非你要求）：把败方的刷怪笼**改写**成胜方内容或**熄灭**——那会改动世界方块，且不可逆。
> 默认采用上表的"运行时拦截"，因为它可逆、可调试、且不破坏你的存档地形。

## 4. HUD（仅主世界）

* 玩家进入某个争夺城（或在触发半径内）时，屏幕**顶部居中**显示该城每个阵营一条血条：
  阵营名（村民/掠夺者/暴徒）+ 当前池/初始池 + 数字；
* 池 = 0 的条变灰并标"已占领"；离开区域或该城结算完毕（只剩一方）**延迟数秒后隐藏**；
* 纯客户端渲染（服务端只同步数据），**不需要资源包**；受 `capture.hudEnabled` 开关控制（默认开）；
* 废土维度**永不显示**（§1）。

## 5. 待确认（会影响实现，但我会先按默认做，不阻塞）

1. **击杀归属**：默认"**任何来源**的该阵营单位死亡都掉池"（战地式：友军互殴也算）。若你只想让**玩家击杀**掉池，说一声。
2. **池归零后玩家是否也能被"终结"**：默认**不判玩家胜负**——幸存方继续刷新，玩家可以继续清（只是对手没了）。
3. **HUD 位置/样式**：默认顶部居中、细条；想要右上角小地图旁或 Boss 条样式（`BossEvent`）也能做。
4. **每城池上限**：默认 `20 + 建筑数 × 2`，夹在 `20..100`；可配置。

## 6. 验收（可静态/无头复核）

1. **维度门控**：废土里**不建池、不同步 HUD、不判占领**（断言调用点都在 `OVERWORLD` 判断之后）。
2. **池算术**：确定性单测——初始值随城市规模、死亡扣减、扣到 0 封顶不为负、跨重启保持。
3. **三条刷新路径统一拦截**：池 = 0 时自然刷怪被取消、刷怪笼 `SpecialSpawn` 被取消、驻军不补员（三条各自断言）。
4. **占领不可逆性**：占领后再次靠近不会重新掷阵营、不会重新建池（账本断言）。
5. **HUD**：只有主世界、只在争夺城、池 = 0 显示"已占领"、离开后隐藏（客户端渲染逻辑单测 + 服务端同步字段断言）。
6. **服务端实测**：RCON 起服 → 主世界放一座城 → 强制触发 → 读日志与 `/armedmobs garrison`（或新的 `/armedmobs capture`）确认池建立；用 `/kill` 清空一方 → 确认该阵营不再刷新、日志出现占领行。**废土重复一次**，确认**没有**池与占领行为。

* 单位真的按楼分配后**互相开打**的观感（AI 交火是否自然）也只能游戏内确认；我能给的是账本/池/刷新路径的门禁与服务端日志证据。
